# 影像训练数据 · 病例切分平台

把病例精确切分为**训练集（组 1）**与**评估集（组 2）**，保证：

- 同一患者的所有病例必须在同一组；
- 患者亲属关系（含传递闭包）相连的病例必须在同一组；
- 两组中标签 0/1 的病例数**精确等于**填写的配额（硬约束，不使用近似比例）；
- 可锁定部分病例的分组；
- 无解时给出**不可再缩减的冲突条件集（MUS）**，逐条标注来源：配额 / 锁定 / 亲属关系。

技术栈：FastAPI + SQLite（WAL）+ z3-solver，原生 HTML/JS 前端，Docker Compose 一键启动。

## 一、快速启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

数据持久化在命名卷 `split-data`（容器内 `/app/data/app.db`）。停止与清理：

```bash
docker compose down          # 保留数据
docker compose down -v       # 同时删除数据卷
```

## 二、本地直接运行（可选）

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

可用环境变量 `SPLIT_DB_PATH` 覆盖 SQLite 文件路径。

## 三、操作流程

1. **数据上传**：上传病例 CSV（`病例号,患者号,标签`，标签仅 0/1，≤200 行），
   再上传亲属对 CSV（`患者A,患者B`，≤200 行）。模板可在页面直接下载，
   示例见 `samples/`。校验失败（空值、重复病例号、标签非法、引用未知患者等）
   整体拒绝，**不会改动已入库的数据**。
2. **配额与锁定**：填写两组 × 两标签的**精确数量**；可在锁定表逐病例指定分组。
   每条锁定绑定**病例号 + 患者号**。每次保存都会产生一个新的输入版本，
   并核对保存所依据的病例表（见下一节）。
3. **求解与发布**：点击“运行 z3 求解”。
   - 有解：展示完整切分清单预览与四格实际计数，可一键发布；
   - 无解：列出不可再缩减冲突条件（删除其中任意一条，其余约束即可满足），
     并按配额/锁定/亲属关系分类，无近似比例方案。
4. **已发布清单**：清单与其**输入依据**（病例、亲属、配额、锁定快照）一起持久化，
   可下载 CSV；失效清单禁止下载但记录保留可审计。
5. **版本记录**：每次输入变动的类型与详情。

## 四、失效语义（关键设计）

- 病例、亲属、配额、锁定中**任何一项变动**都会使输入版本 `+1`；即使改回原值，
  版本号也不回退（每次保存都是一次新的写操作，均有版本日志）。
- 版本一旦变动：
  - 所有旧预览令牌立即作废，不能再发布；
  - 所有已发布清单在同一数据库事务内被标记 `invalidated`，不能再下载；
  - 服务重启会清空内存中的预览令牌，重启后不存在可发布的旧预览。
- 求解在数据库事务之外执行：计算期间允许修改输入。若计算期间版本发生变化，
  本次结果直接作废（HTTP 409），不生成预览。
- 发布时在 `BEGIN IMMEDIATE` 事务内再次核对版本与病例表指纹，堵住“检查后、写入前”
  的交错窗口；两个浏览器窗口同时操作也不会放出过期或半份清单。

### 病例表更换（本版本新增）

- 病例表有一份**内容指纹**（`case_table_id`，只由病例号/患者号/标签决定）与
  一个**代次**（`case_table_epoch`，仅换表时 +1）。配额、亲属、锁定的变动都不改它们。
- **锁定绑定身份**：每条锁定记录 `病例号 + 患者号 + 分组`。换表时只有病例号与
  患者号**都相同**的锁定保留；病例号改指另一位患者时，原患者的锁定被丢弃，
  绝不跟随病例号进入下一份训练/评估清单。
- **保存锁定核对病例表**：提交可携带 `case_table_id`；与当前病例表不一致时
  **整次拒绝**（HTTP 409，`code=STALE_CASE_TABLE`），不落库、不递增版本，
  现行锁定、输入版本与已发布清单照旧。逐条提交若携带 `patient_id`，也会核对
  该病例号当前指向的患者。
- **改配额不会让锁定提交过期**：判定只看向指纹，不看版本号；同一病例表上
  单独修改配额/亲属关系后，锁定提交依然有效。
- **网页刷新/换表**：锁定草稿绑定病例表。换表后草稿整体作废，原患者未保存的
  选择不会出现在同号新患者那一行；草稿只记录用户实际改动过的行，
  不会压掉另一个窗口刚保存的锁定。
- 求解与发布使用当前（新）病例表与仍有效的锁定；清单记录其依据的
  `case_table_epoch` / `case_table_id`。

## 五、API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 当前输入版本、病例表指纹/代次、数据概览、清单列表 |
| POST | `/api/upload/cases` | 上传/替换病例 CSV（multipart）；返回保留/丢弃的锁定 |
| POST | `/api/upload/relatives` | 上传/替换亲属对 CSV（multipart） |
| PUT | `/api/quotas` | 保存四格精确配额 |
| PUT | `/api/locks` | 保存完整锁定表；可带 `case_table_id` 核对病例表 |
| POST | `/api/solve` | z3 求解，有解返回预览令牌 |
| POST | `/api/publish` | 按预览令牌发布（过期返回 409） |
| GET | `/api/manifests` | 已发布清单列表（含失效标记、病例表代次/指纹） |
| GET | `/api/manifests/{id}` | 清单 + 输入依据明细 |
| GET | `/api/manifests/{id}/download` | 下载切分 CSV（失效返回 409） |
| GET | `/api/version-log` | 输入版本变动记录 |

`PUT /api/locks` 请求体示例：

```json
{
  "case_table_id": "9fd3905588887b84…",
  "locks": [{"case_id": "C3", "patient_id": "P2", "group": 2}]
}
```

病例表已被替换时返回 `409 {"code": "STALE_CASE_TABLE", ...}`，整次提交不生效。

## 六、自测

```bash
pip install pytest httpx python-multipart
python3 -m pytest tests/ -v
```

覆盖：连通分量与传递关系、精确配额、锁定、三类来源的 MUS 及其不可再缩减性、
上传校验与行数上限、发布/下载全链路、输入变动后预览与清单永久失效、
重启持久化、并发写版本一致性；以及本版本的换表语义（锁定不跟随病例号迁移、
换表只保留同病例号+同患者号的锁定、旧表锁定提交整次拒绝且不改动现状、
改配额不使锁定提交过期、重新求解/发布使用新表与仍有效锁定、
前端锁定草稿不跨表泄漏）。共 42 个用例；其中前端草稿逻辑 9 个用例需要本机
有 `node`（无 node 时自动跳过）。

## 七、Docker 说明

`docker compose up --build` 会在 `python:3.11-slim` 中按 `requirements.txt`
安装依赖、复制 `app/`，并把 `/app/data` 挂到命名卷 `split-data`。
若宿主环境的 Docker 守护进程不可用（例如受限沙箱），可先按“二、本地直接运行”
启动同一份代码进行体验。
